# M13b — UX, performance, mobile & bug bash

Soak-tested every city to victory and defeat, fixed the leaks and crashes that turned up, the
known UX issues (advisor over the wave button, clipped alerts, close portrait zoom, ledger,
trackpad pan), touch ergonomics and accessibility, plus the head/loading polish. Screens:
`docs/progress/m13b-*.png`.

## 1. Soak / bug bash — `tools/soak.mjs` (`npm run soak`)

Headless Chromium (SwiftShader) runs real games and records console errors & warnings, page
errors, unhandled rejections, failed requests, the JS heap after forced GC, Pixi scene-graph
nodes, live GPU textures (and any sprite still showing a destroyed texture), DOM listeners,
workers, audio nodes, long tasks, frame deltas, the bot's decision times and per-frame JS
(`game.perf`: sim / view / UI / render).

```
node tools/soak.mjs                          # flows + escalate (victory) & passive (defeat) per city
node tools/soak.mjs --only flows|games|perf|touch [--cities paris] [--speed 40] [--json out.json]
node tools/soak.mjs --no-build --dist <dir>  # reuse a build (own outDir: no clash with dist/)
```

- **flows**: title → Enter → city select → 1 (Madrid) → Esc pause → settings → close → resume →
  3× restart (heap after GC each) → other city → London → defeat → end screen → skip → Enter
  (play again) → quit to title.
- **games**: `?city=X&autoplay=1&bot=escalate|passive` (new `?bot=` param), loop time scale
  40×, then the end screen at 1× (newspaper → ledger → buttons); asserts the outcome, that the
  end screen finished and that the Hate ledger adds up.
- **perf**: `?stress=3000` (camera on the crowd, and zoomed out with all 3000 drawn) and the
  title-screen attract bot, 15 s each at 1440×900.
- **touch**: every visible tappable UI node on phone landscape/portrait (title, select, HUD,
  deploy, pause, settings, end) must have a hit rect ≥ 44×44 CSS px.

## 2. UX fixes

- **Advisor vs LET THEM COME / CALL EARLY** (`UiApp.advisorDefault`): the default spot narrows
  the bubble to end left of the wave button, or — when that leaves < 186 UI px (phones, the
  desktop's wide red button) — lifts the advisor above the button and its countdown. The
  tutorial's own placement still wins during the briefing. `m13b-advisor-*.png`.
- **Alerts / codex toasts clipped at the left edge**: they used to slide in from fully off
  screen, so any frame caught mid-slide showed a card cut by the screen edge. Now a 16-px slide
  - fade. `m13b-alerts-desktop.png`.
- **Portrait zoom**: the default zoom keeps ≥ 10.5 tiles across the screen _width_
  (`render/zoom.ts MIN_TILES_WIDE`): iPhone 390×844@3 → zoom 3 (≈ 12 tiles) instead of 4 (9).
  Landscape/desktop unchanged; rotating mid-game keeps the player's zoom.
- **Void beyond the map** (M13a note): the camera centre is also clamped to the iso diamond
  (`Camera.diamond`, inset 0.6 × the view's half-extent in tiles), so `focus=crowd` / portrait
  views near the edges show at most a sliver of void. `m13b-portrait-crowd.png`.
- **Ledger**: accounting verified (sim: `gainHate`/`spendHate` are the only paths; soak +
  unit test assert `100 + earned − spent = held`). The ledger now adds a **Hate unspent** row
  so the three lines add up for the player.
- **Trackpad**: two-finger scroll pans; pinch (ctrl+wheel) and mouse notches zoom
  (`classifyWheel`, sticky for the rest of a scroll gesture). Smoke-tested.

## 3. Performance

Per-frame JS at 1440×900 (15 s probes, `--only perf`; SwiftShader is GPU-bound at 2–6 fps
here, so `render` includes GL sync waits that a real GPU does not have). "Before" = HEAD before
M13b (its `view` includes the UI frame).

| Scene                                | sim / tick before → after | view (+UI) before → after | render before → after | draw calls |
| ------------------------------------ | ------------------------- | ------------------------- | --------------------- | ---------- |
| `stress=3000`, zoom 1, 3000 drawn    | 2.19 → 2.24 ms            | 3.28 → 3.06 + 0.76 ms     | 6.95 → 7.48 ms        | 7 / frame  |
| `stress=3000`, default zoom on crowd | 2.31 → 2.02 ms            | 1.27 → 1.65 + 0.65 ms     | 1.68 → 3.19 ms\*      | 6 / frame  |
| title attract bot                    | 0.17 → 0.20 ms            | 3.68 → 4.78 + 0.08 ms     | 5.51 → 5.30 ms        | 3 / frame  |

\* the camera now sits further inside the map, so 888 protesters are on screen instead of 39.

- **Bot hitch**: the escalate bot's worst decision in full games was 10.7–15.2 ms (1–5
  decisions > 8 ms per game); `placeRoad` now stamps unit spacing / proximity into
  generation-stamped grids instead of scanning hot tiles × ground units — identical decisions
  (state hashes match HEAD for 4 city/bot pairs), worst decision **5.9–6.4 ms, none > 8 ms**.
  The sim is a deterministic ~2.2 ms/tick at 3000 protesters (CPU profile: `updateCrowd` is the
  only hot JS; main thread 87 % idle waiting on SwiftShader).
- **Batching**: 3–7 draw calls per frame with 3000 sprites — no batch breaks to fix.
- **Hot spot left for the art owner**: in the title scene ~3–4 ms/frame is
  `flushSilhouettes()` (src/view/silhouette.ts, M13a) — each new silhouette re-uploads a whole
  1024² page (4 MB). Suggest dirty-rect `texSubImage2D` or 256² pages.
- **Dynamic quality fallback** (`game/governor.ts`, unit-tested): an EMA of frame times above
  42 ms for 4 s steps the view down (level 1: half-rate crowd animation, FX budget and live
  bodies halved, no x-ray ghosts; level 2: FX/bodies at a quarter); below 22 ms for 30 s steps
  back up. Pixel-perfect rendering rules out resolution scaling. On by default, off under
  automation (`navigator.webdriver`); `?governor=1|0` forces it.
- **Quality tier** (`classifyQuality`, unit-tested): phones by UA or coarse pointer + small
  screen → `mobile` (1500 concurrent protesters, FX 400, bodies 300); ≤ 2 cores, ≤ 2 GB, or a
  ≤ 4-core / ≤ 3 GB phone → `low` (800, 220, 150, no ghosts, anim LOD always); touch laptops
  and big tablets stay `desktop`.

## 4. Mobile ergonomics

- **Touch targets**: the soak's touch audit now passes on both phone orientations. Fixed: the
  top-bar Legitimacy/Capitol meters (hit rect padded to ≥ 44 CSS px), the settings sliders and
  option chips (touch rows 27 UI px with tall hit areas; phone landscape lays the settings out
  in two columns). `m13b-settings-phone-*.png`.
- **Page visibility**: hidden tab / `pagehide` mid-run opens the pause menu (the audio engine
  already suspends its context); Shift-keep-placing is reset.
- **Orientation change**: re-layout immediately and again 350 ms later (iOS reports new
  safe-area insets late); zoom kept.
- **No context menu / text selection / double-tap zoom** anywhere on the page.
- iOS audio unlock: verified the path (silent buffer inside the gesture, listeners stay armed
  to re-resume after interruptions). Safe areas, UI-through-taps, long-press tooltips and
  pinch/drag were already covered (M1/M9) and are smoke-tested.

## 5. Accessibility & settings

- **Reduced motion**: screen shake, hit-stop freeze frames, the HUD Capitol shake and the
  deploy-card error shake all respect SCREEN SHAKE OFF; the first run follows the OS
  `prefers-reduced-motion`.
- **Colour-blind-safe cues**: an iso **✖** over an invalid placement spot (ground and roofs),
  a **▼ chevron** over the selected ally, and a **"!" diamond** over enemy x-ray ghosts (allies
  get M13a's chevrons) — team and validity never rely on blue/red or green/red alone.
  `m13b-cues-invalid.png`.
- **UI SIZE: AUTO / LARGE** (settings, replaces the single-value LANGUAGE row): one integer UI
  scale step up wherever ≥ 190 × 400 UI px remain (e.g. 844×390@3 → 422×195 UI px,
  `m13b-ui-large-landscape.png`); screens too small for it keep AUTO. The screen-FX layer
  (Hate fists) follows the app's scale.
- **Remembered**: last city (title backdrop, M9) and now the last chosen game speed (start
  speed of the next run).

## 6. Audio mix

- The crowd bed (ambience bus) ducks under the advisor's typing (−7 dB, re-armed per tick, so
  it stays down while he talks) and the bell, UI clicks (−3 dB) and stamps (−4 dB).
- Music phase per screen, by code path: title / city select / credits `menu`
  (`showTitle`), run start `prep`, then `bindGameAudio` each second: director phase
  `prep`/`wave`/`breather`, `victory`/`defeat` from the world (end screen). Unit-tested
  (`tests/m13b.test.ts`).

## 7. Loading, head & tooling

- Loading bar eases to the reported progress and creeps through the current job (coarse job
  reports used to freeze it), tips rotate every 6 s.
- `index.html`: inline ink background (no white flash before CSS), `<title>`, meta description,
  favicon, apple-touch-icon, web manifest (`public/manifest.webmanifest`).
- **Icons from the art pipeline**: `npm run icons` (`tools/icons.mjs`) renders the Riot
  Control officer portrait (RIOT-64, nearest, integer scale) on ink into
  `public/icons/{favicon-32,apple-touch-icon,icon-192,icon-512}.png`.
- `npm run shots` no longer screenshots the full-page gallery by default (one screen of the
  units group instead); `--gallery` restores it.
- New params: `?bot=KIND`, `?governor=1|0`. `game.perf` now also has `ui` and `ticks`;
  `view.timing` splits `overlays` / `decals` out of `other` (silhouette flush).

## 8. Remaining issues / notes

- SwiftShader can't measure GPU cost; the perf table is main-thread JS only.
- `flushSilhouettes` page uploads (M13a file, see §3).
- Juice "+N" label textures are cached per distinct amount (bounded, ~100–150 tiny textures by
  the end of a long run).
- The UI LARGE setting has no effect on the smallest phones (the layout would not fit).
- The governor is disabled in all headless tooling; it was exercised by unit tests only.
- `tools/soak.mjs` full run ≈ 9 min (flows 70 s + six games 35–130 s each).
